## 背景与目标

当前报告已经具备 19 幅图、11 张表和 5 处代码清单，但多数流程图采用朴素的单色 TikZ 盒图，数据图与正文叙事之间的层级不够明显。目标是在不改变任何数据和证据含义的前提下，把图表统一为“问题—判断—动作—证据”的叙事系统，使非智能体方向的信息安全评委先看懂风险后果，再理解三级级联、OpenClaw 执行点和 P6/P7 证据。

## 参考风格提取

两份参考报告提供互补的视觉线索：

1. `基于电子指纹的追踪定位系统项目报告.docx` 使用深色技术画布、青蓝/绿色节点、编号流程、网络关系图和运行截图，适合表达系统拓扑、执行链和工程证据。
2. `2015第八届竞赛作品报告.doc` 使用浅色页面、青色圆角模块、洋红色代码强调、粉色连接箭头、多面板折线图和分组柱状图，适合表达模块关系、算法流程和统计结果。

本报告采用两者的互补特征，但不复制其具体图形：正文以浅底叙事图为主，P6/P7 和运行证据使用深色证据面板，所有图同时满足彩色阅读和灰度打印。

## 视觉基线

### 色彩语义

| 语义 | 颜色 | 用途 |
|---|---|---|
| 输入/系统/执行点 | `#237A8E` | 青蓝主色，表示正常数据流和系统模块 |
| 允许/通过 | `#3C9D70` | 绿色，表示继续业务或达成阈值 |
| 升级/询问 | `#E59B45` | 橙色，表示需要更多判断或人工裁量 |
| 阻断/高危/未达阈值 | `#C44A53` | 红色，表示副作用被阻断或指标未达冻结阈值 |
| 证据/哈希/重放 | `#263645` | 深蓝，专用于 P6/P7 和签名证据 |
| 画布 | `#F7F9FB` | 浅灰白，保持报告页面清爽 |

颜色不作为唯一编码。通过文字标签、箭头样式、边框和节点形状重复表达状态；不使用饼图、3D 图、彩虹色图例或无意义装饰。

### 图形语言

- 流程图采用带编号的圆角模块、方向箭头和结果标签。
- 每张图顶部保留一句“读图结论”，帮助评委先理解结论再阅读细节。
- 失败闭合统一使用虚线和红色边框；询问统一使用橙色菱形或状态卡。
- 数据图使用横向排序、直接标注、阈值线/阈值带和分子分母说明。
- 截图保留原始像素，不对攻击证据内容做重新绘制；外层增加场景编号、攻击后果、终局动作和工具执行次数条带。

## 可复现绘图链

新增 `report/scripts/plot_report_figures.py`，只使用报告现有实测数据：

- 整体指标：`88.33%`、`93.33%`、`1.67%`、`90.74%`、`99.33%` 及对应分子、分母和冻结阈值。
- 逐类召回：九类风险的 `100/95/95/95/90/90/85/75/70%`，统一阈值为 `80%`。

脚本输出矢量 PDF 到 `report/figures/`，正文通过 `\includegraphics` 引用。脚本不联网、不读取外部数据、不生成新的实验结果；每次运行都应得到相同的图形和数值标注。

## GPT 图片占位

只预留位置和提示词，不在本轮生成图片。提示词保存在 `report/visual-prompts.md`，正文预留两个可替换位置：

1. 第一章背景：展示不可信外部内容如何沿智能体规划链进入真实工具动作，要求信息安全流程图风格，不能出现真实品牌、学校标识或可识别个人。
2. 第五章总结：展示同一运行时安全中间件如何通过适配层连接不同智能体框架，要求工程架构信息图风格，不能暗示尚未完成的框架集成已经实测。

占位区域在缺少图片文件时显示“待生成介绍图”和简短用途说明；图片加入后通过 `\IfFileExists` 自动替换，不改变图号和正文引用。

## 验收标准

1. 19 幅既有图、11 张表和 5 处代码清单均保留，图号、标签和引用不漂移。
2. Python 脚本运行成功，输出图中的每个数字与正文表格逐项一致。
3. 不新增数据主张，不修改评测结果和攻击证据。
4. 重新编译后 LaTeX 错误、未定义引用和 overfull box 均为 0。
5. 逐页渲染检查无空白页、重叠、截断和孤立图注；应用前景和第二章衔接正常。
6. 彩色版和灰度版均可区分允许、询问、拒绝、通过和未达阈值。
7. GPT 图片占位可见，提示词文件完整，未生成任何外部图片资产。
