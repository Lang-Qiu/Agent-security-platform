# 05 — Sandbox Engine 技术事实报告

本报告只陈述有代码或实测证据的事实。所有测试数字为本次审计实际执行结果。不使用宣传语。

---

## 1. 项目解决的问题

大模型智能体在执行任务时会持续消费三类不可信输入：用户提示、模型自身输出、以及工具调用请求。这些输入可以携带提示注入、越狱、指令覆盖、记忆投毒、工具劫持、越权参数、信任边界穿越、敏感数据外泄等载荷。传统防护手段在这个场景下有三个具体缺口：

1. **规则扫描单点失效**——正则/关键词规则可被同义替换、分词切断、编码变形绕过；而单纯依赖 LLM 判定则不可复现、不可审计、且判定器自身会被注入。
2. **把内容交给外部模型判定，等于把敏感数据交出去**——绝大多数「LLM-as-judge」方案直接把原始上下文发给外部 API。
3. **判定结果不可核验**——一次判定产出「拦截/放行」，但没有机制证明这个结论与内部证据一致，也无法在事后重放验证。

本项目针对的正是这三点：在**不把原文交给外部模型**的前提下，让确定性规则、本地模型、外部判官三层协同产出**可重放、可自校验、fail-closed** 的决策。

## 2. 目标场景

- 智能体运行前/模型输出投递前/工具执行前/消息投递前的四个生命周期关卡处进行内容评估（执行链代码已实现，见 §7 边界）。
- 平台化调用：后端提供能力令牌鉴权的评估 API 与审计查询 API，前端提供评估工作台与审计视图。
- 三种部署形态按可用资源降级：`rule_only`（纯确定性）→ `local`（+ 本地模型）→ `local_and_judge`（+ 外部判官）。

## 3. 真实架构

### 3.1 分层

```
调用方（前端工作台 / 后端 API / OpenClaw 插件）
        │
后端 sandbox-security 模块（10,057 行 / 34 文件）
  有序准入：全局限流 → bearer 鉴权 → scope → 存储健康 → 每能力限流
           → 幂等键 → 读体(786KB/5s) → schema → stage+profile 授权
  评估编排：simulation 权威构造 → canonical 指纹 → 幂等占位
           → 并发闸(4) → 调用引擎 → 决策校验 → 审计与幂等同事务提交
        │
引擎装配层 security-production（9,983 行 / 17 文件）
  env-only 配置（密钥 WeakMap 暂存、首次构造即删除）
  三模式装配：rule_only / local / local_and_judge
        │
引擎核心 security（8,479 行 / 21 文件）
  ① 权威绑定  ② 输入边界(句柄化/nonce/canonical hash)  ③ profile 解析
  ④ 三 slot 串行：rule → local → judge
  ⑤ 发布(主体令牌序数化 + 确定性排序)  ⑥ 策略归约  ⑦ 语义自校验
```

### 3.2 单次评估的真实调用链

后端入口 `POST /api/sandbox/security/evaluations` 到引擎，共 28 跳（详见 `03-scope-map.md`）。引擎内部 `evaluate()` 的关键路径：

1. **ID 前阶段**（失败即抛错，不产出决策）：取消检查 → 死线控制器 → 权威绑定 → 输入边界准备 → profile 解析 → 账本/检测器解析/信任等级派生 → `decision_id` 生成并正则校验。
2. **rule slot**：确定性规则匹配 → 输出边界规范化 → 证据资格判定。若命中严重度达到 `short_circuit_min_severity`，**短路**，跳过后两槽。
3. **local slot**：本地模型（Ollama `qwen3:8b`，digest 双校验）在 slot 租约内执行。
4. **judge slot**：仅当存在未决信号时进入。派生 `etok:` 外部令牌注册表 → 物化 routed obligations → **把 etok 引用反向映射回私有句柄并重算 `subject_key`**（防同类别碰撞）→ 确定性脱敏 → 脱敏载荷校验 → 外部判官 → 输出规范化 → 应用判定并关闭状态机。**缺少 sanitizer 即 `external_redaction_failed`，绝不裸发。**
5. **终结化**：引擎失败时，所有未记录 slot 标为 `evaluation_terminated`，运行中的标为 `timeout`，状态机强制关闭。
6. **发布**：主体实体排序 → 序数化公共令牌（`source://…/0001`）→ findings 确定性排序 → 分配 `evidence://sandbox/security/<decision_id>/NNNN`。
7. **归约**：最高已接受严重度 → action matrix；未决信号或失败/超时/无效运行抬升 action 并给风险下限；引擎失败强制 `indeterminate`；末位守卫拒绝「有风险却放行」。
8. **语义自校验**：重新推导 qualification/escalation/publication/reducer 并与决策比对；不一致则走一次有界恢复（以 `semantic_validation_failed` 重新归约并复校），否则抛错。

### 3.3 部署形态

三个公开模式由 env 决定，判官需五项配置全部通过校验且 `SANDBOX_SECURITY_ENABLE_JUDGE === "1"`，缺一即 fail-closed。源码中不含任何 provider URL、外部模型默认值或凭据（硬编码 URL 仅本地 Ollama `127.0.0.1:11434`）。另有两个非公开装配：live-capture 与隔离网络重放，测试断言其不进入公开导出面。

## 5. 创新点（相比传统方法的差别）

**创新点 1：把「外部 LLM 判定」做成不泄露原文的可验证过程。**
传统 LLM-as-judge 直接把原始上下文发给外部 API。本项目在判官之前强制插入确定性脱敏器：10 类敏感信息（私钥块 / Bearer 与 Basic 凭据 / URL 内秘密 / JWT / 邮箱 / 电话 / IPv4+IPv6 / UUID / 高熵串 / 文件路径）按固定管线顺序替换为占位符，并对**输出侧**做回泄验证——把占位符剥离后再做 NFKC 归一、百分号解码、base64 解码，任何敏感原子以任何形式重现即整体硬失败。判官收到的只是 `etok:` 令牌与结构化 obligation，反向映射由本地注册表完成。差别在于：**脱敏不是「尽力过滤输入」，而是带出口校验的双向断言**。

**创新点 2：模型输出被当作不可信数据处理，而非当作结论。**
传统做法把模型返回的 JSON 直接当判定结果。本项目对判官/本地模型的返回值施加三层约束，其中第三层是关键：每个返回的 `obligation_id` 必须在本地预计算的绑定表中命中，否则整份作废；**风险类别与受影响主体取自本地绑定，而不是取自模型**，模型只能在闭合枚举内提供 outcome / severity / confidence，信心词再映射为固定数值。这使得模型无法凭输出扩大自己的权限，也无法编造不存在的主体。

**创新点 3：决策产出后再由引擎自证一致性。**
一次评估结束后，语义校验器重新推导资格判定、升级状态、发布映射与策略归约，与已生成的决策逐项比对；不一致则以 `semantic_validation_failed` 重新归约并复校一次，仍不一致就抛错而不返回。配合 canonical JSON、内容哈希 `finding_id` 与完全确定的发布顺序，同一输入在同一配置下产出同一决策。差别在于：**这不是「记录日志供人事后看」，而是引擎在返回前先自我否证**。

**创新点 4：语料与标签的可复现性做到哈希级。**
300 例语料全部来自四个公开研究数据集（AgentDojo / ToolEmu / deepset prompt-injections / OASST1），每条记录带上游 SHA-256 与许可证证据，数据集 revision 被锁定；标签树与输入树分别哈希，标签按 `fixture_sha256` 绑定到具体输入，捕获阶段对标签不可见。差别在于：**语料不是自己编的，且第三方可按配方独立重建**。

## 6. 已实现边界

- 引擎核心、生产检测器装配、后端 API 与持久层、前端工作台与审计页，**均为可运行实现，非骨架**：三大区块共 28,519 行，全区扫描 `TODO/FIXME/STUB/not implemented` 结果为 **0 命中**，无空函数体。
- 检测器共三类且全部真实：确定性规则（9 类别各 1 条）、本地 Ollama 模型（digest 启动与逐响应双校验）、外部 OpenAI 兼容判官（仅两种协议白名单 + HTTPS/FQDN 端点策略）。
- HTTP 传输走 `node:http`/`node:https`，无 `fetch`；17 个生产 spec 全部密闭（不需要真实模型），测试通过注入 `request_factory` 避免开套接字。
- 后端 6 条路由：公开 2 条（评估、审计查询），内部 4 条（能力签发、吊销、审计清理、执行事件接收）。内部路由不可从公开监听器到达。
- 全链只存在 `evaluation_mode: "simulation"` 一种权威模式，服务层主动拒绝任何非 simulation 决策。

## 7. 未实现 / 未来工作边界（必须诚实标注）

1. **不存在操作系统级沙箱**。仓库文档曾声称监控「文件访问、命令执行、网络行为、进程生成、权限提升」——代码中没有任何 syscall / 进程 / 文件 / 网络拦截，`samples/sandbox/` 只有 `.gitkeep`。真实形态是**内容评估 + 内存态仿真工具**。「阻断」只体现为返回 `deny`/`ask` 语义，以及宿主补丁在 `execute()` 前返回 blocked。
2. **OpenClaw 执行链未在本 checkout 生效**。补丁目标 `2026.6.34`，实装 `2026.6.10`；抽查 4 个补丁目标文件全部缺失；`general-security/node_modules` 不存在；补丁从未被应用。阻断断言测试因 fixture 前置断言不成立而无法运行，未观测到通过运行。另注：补丁中有一处 hunk 删除了整个出站投递队列，与安全屏障无关。
3. **无任何已接受的检测质量证据**。全仓不存在 `seal.json` / `receipt-chain.json` / `evaluation-report.json`；指标仅以散文形式存在于 `docs/progress.md`，三次运行**全部未通过自定阈值**。最佳一次（2026-08-02）：unsafe recall **0.8444 < 0.90**、jailbreak **0.60 < 0.80**、instruction_override **0.65 < 0.80**；达标项为 high/critical recall 0.95、transformed 0.8889、safe FP 0。结论为 `evaluation_not_accepted`，evidence root 条目数为 0。
4. **当前有 15 个引擎测试与 60 个后端测试为红**。引擎 15 红同源于一次把超时预算放大 40–360 倍的提交（work budget 5000→360000ms）而未同步测试，该提交自身 message 已承认留下红灯；副作用是普通生产档位与 P6 live-capture 档位现已数值相同，且隔离重放路径在普通装配下因 `qualification_timeout_ms` 硬校验而不可用。后端 60 红全部是同一条 Windows POSIX 目录权限门，非逻辑缺陷，但意味着 **SQLite 持久层在本机未被验证**。
5. **审计日志不是防篡改账本**。普通 SQLite 行，无哈希链、无签名、无触发器，purge 路径存在 `DELETE`。可诚实表述为「仅追加、读取可审计、分页防伪」。
6. **能力令牌不是 HMAC 令牌**。`randomBytes(32)` 不透明串，验证为 SHA-256 摘要 → 索引等值比对，非 constant-time，无 nonce / 时间窗 / 请求签名重放防护。管理员 bootstrap token 为单一共享静态密钥。
7. **限流与并发闸均为进程内**，水平扩容会成倍放大实际上限。
8. **公开评估 API 目前没有消费方**——执行插件在进程内直接调用引擎，从不调用该 API。
9. **执行侧审计 fail-open**：审计后端不可达时，allow 决策不留记录。
10. **规则集为演示级广度**：9 类别各 1 条，命中条件很窄（例：提示注入需同时含三个词；越权只匹配参数键 `sudo`）。类别覆盖完整，类别内检测广度薄。
11. **前端 showcase 页数据为手写 fixture**（含耗时数值），页面自带「演示数据」标注且有测试强制保留；相关文件目前未提交。
12. **参考文献中的 LLMmap（USENIX Security 2025）未实现**，源码 0 命中，且该文献属资产测绘赛道背景阅读。
13. **Track1 的「准确率 1 / 召回 1 / FPR 0」属另一引擎**：9 个用例 + 9 条 base-filter 规则，不含 LLM，不是 300 例语料。严禁与 sandbox-security 能力混用。

## 8. 最值得宣传的亮点（按评委易理解度排序）

1. **「外部大模型参与判定，但拿不到原文」**——确定性脱敏 + 出口回泄验证 + 令牌化边界。一句话能讲清，48/48 与 56/56 两组绿灯测试可直接引用，且解决的是一个评委立刻能共鸣的真实矛盾。
2. **「模型说了不算，得对得上账」**——obligation 绑定表使类别与主体只能来自本地，模型无法扩权或编造主体。
3. **「引擎在返回结论前先自己否证一遍」**——决策后语义自校验 + 完全确定的发布顺序，使同输入同配置同结论、可重放。
4. **「多检测器分层协同 + 全程 fail-closed」**——规则 / 本地模型 / 外部判官三层串行，高危短路，任何环节失败都只会让结论更严格（末位守卫拒绝「有风险却放行」，strict ≥ balanced 由 import 期数学断言保证）。
5. **「语料可被第三方按哈希重建」**——300 例 9 类别，四个公开研究数据集 revision 锁定，标签树独立哈希、对捕获阶段不可见。
