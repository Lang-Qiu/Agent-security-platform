# 08 — 夸大风险表述清单与稳妥改写

> 用法：定稿前用本表逐条自查。左列任何措辞若出现在海报上，按右列替换。
> 分级：🔴 严重（构成虚假陈述，评委一问即穿）/ 🟠 中度（有实现但被放大）/ 🟡 轻度（易被误读，需限定语）

---

## 🔴 严重风险（禁止出现）

### R1 「运行时沙箱」「行为阻断」「进程/文件/网络监控」
**风险原因**：`engines/sandbox/README.md:5-7` 声称监控文件访问、命令执行、网络行为、进程生成、权限提升。**代码中不存在任何 OS 级插桩**——无 syscall 拦截、无进程监控、无网络钩子，`samples/sandbox/` 仅有 `.gitkeep`。真实形态是对注入的内容记录做评估，加内存态仿真工具。评委一问"怎么拦截系统调用"即当场崩塌。
**稳妥改写**：
> "在智能体生命周期的关键节点上做内容与工具调用的安全判定，输出允许/告警/询问/拒绝四类结论。判定结论由运行时侧执行，引擎自身不做操作系统层插桩。"

### R2 「准确率 100% / 召回率 100% / 零假阳性」
**风险原因**：该组数字出自 Track1 的 **9 个受控用例 + 9 条确定性规则**（非 LLM、非 300 例语料），源文档自身已限定"指标仅适用于受控数据集"。而 300 例语料的最佳记录为 unsafe recall 0.844（阈值 0.90 未达）、jailbreak 0.60、instruction_override 0.65（阈值 0.80 未达），该次运行结论是 `evaluation_not_accepted`。跨数据集挪用等于伪造。
**稳妥改写**：
> 方案一（推荐）：完全不提检出效果数字，改述机制与可复现性。
> 方案二（若必须提）："在 9 例受控规则场景中动作判定完全一致；300 例语料的检测质量仍在调优，尚未达到项目自设阈值。"

### R3 「已通过评测验证」「已密封签名证据」「基准测试已达标」
**风险原因**：全仓无 `seal.json`、无 `receipt-chain.json`、无 `evaluation-report.json`。`docs/progress.md:9063` 自述"the evidence root has zero entries"。三次记录运行**全部 FAILED**。所有 plan/spec 状态均为 `PENDING`/`PROVISIONAL`，无一条 `VERIFIED`。
**稳妥改写**：
> "评测语料、隔离重放门禁与签名证据格式均已实现且默认失败关闭；正式验收证据尚未产生。"

### R4 「防篡改审计」「不可篡改账本」「区块链式日志」
**风险原因**：审计事件是普通 SQLite 行。全模块 grep 无哈希链、无 `prev_hash` 列、无签名列、无触发器；purge 路径可 `DELETE`。拥有库文件写权限者可一致地增删改而不留密码学痕迹。
**稳妥改写**：
> "仅追加的结构化审计事件日志：读取动作本身在同一事务内被记录，分页游标带消息认证码防伪造与跨主体重放，行内容与 JSON 载荷在读取时交叉校验，数据库绑定部署密钥。"

### R5 架构图画「插件 → 后端公开 API → 引擎」
**风险原因**：`POST /api/sandbox/security/evaluations` **全仓零调用点**（node_modules 外）。运行时插件在进程内直接构造并调用引擎，与后端之间**只有审计事件**一条连线。画成串联属虚假连线。
**稳妥改写**：见 `07-poster-image-plan.md` 图 1 的双入口拓扑，插件→后端连线标注"仅审计"。

### R6 「已部署到智能体运行时」「已在真实运行时生效」
**风险原因**：补丁目标版本 `2026.6.34`，实际安装 `2026.6.10`；抽查 4 个补丁目标文件全部缺失；`general-security/node_modules` 不存在；补丁在本 checkout 从未应用；相关阻断测试因 fixture 前置断言失败而无法运行。
**稳妥改写**：
> "针对特定运行时版本的强制执行方案已在代码层完成，含摘要校验的构建流程与四道生命周期栅栏；当前环境尚未完成构建与实机验证。"

## 🟠 中度风险（有实现但被放大）

### R7 「HMAC 认证的能力令牌」「密码学签名令牌」
**风险原因**：令牌是 `randomBytes(32)` 生成的不透明串，验证方式是 SHA-256 摘要 → 索引 SQL 等值查询，**不是 HMAC，不是恒定时间比较**，无 nonce、无时间窗、无重放计数器。真正的 HMAC 用于派生值（游标 MAC、幂等键、指纹），不保护令牌本身。
**稳妥改写**：
> "带作用域、阶段与策略档位限制的能力令牌，支持有效期与主动吊销；明文仅在签发时返回一次，服务端只保存摘要。"

### R8 「全链 fail-closed」
**风险原因**：方向不一致。策略判定确实 fail-closed（引擎失败→不确定、风险+允许被禁止、脱敏失败→判官零调用、栅栏失败→拒绝为底线）；但**执行侧审计是 fail-open**——审计后端不可达时 allow 决策不留记录。
**稳妥改写**：
> "策略判定链路 fail-closed：任一检测器失败、超时或结果不合法，都会把结论向更严方向抬升而非放行。"（限定为"策略判定链路"）

### R9 「策略引擎」「可配置策略系统」
**风险原因**：两个档位是硬编码常量，非从 `engines/sandbox/policies/`（空目录）加载；槽位数固定为 3，槽 ID 是闭合三元字面量联合，档位解析是两键查表。是"固定的一对档位"，不是策略系统。
**稳妥改写**：
> "两级策略档位（均衡/严格），二者的严格性偏序关系在模块加载时被数学校验，严格档不可能比均衡档更宽松。"

### R10 「内容泄漏检测」
**风险原因**：`detector-output-boundary.ts:255-262` 仅扫 `raw_content`、`PROMPT_SECRET`、`password=` 三个字面量，加句柄前缀 `hsrc:`/`hcall:`。句柄前缀检查有实质意义，字面量部分是演示级。而 `deterministic-sanitizer.ts` 的出口回泄验证是**真的**（多重解码后复查全部脱敏原子）——两者别混为一谈。
**稳妥改写**：
> 把宣传落在脱敏器的出口回泄验证上："每一处被脱敏的值都会被登记，输出在剥离占位符并经多重解码后复查，一旦重现即硬失败。"不要泛称"内容泄漏检测"。

### R11 「隔离网络重放门禁已验证」
**风险原因**：两重障碍。其一，脚本用 Linux `unshare --net`，Windows 无法执行；其二，`benchmark-composition.ts:1056` 硬要求 `qualification_timeout_ms === 1000`，而普通装配现传 `40000`，构造阶段即抛错——**该路径当前不可执行**。
**稳妥改写**：
> "评测重放设计为在无网络命名空间中运行、凭据全部清空；该门禁需 Linux 环境，当前配置下尚未跑通。"或干脆不提。

### R12 「多检测器协同」暗示并行/投票/集成学习
**风险原因**：三槽是**严格串行**，order 固定为规则→本地→外部，且有短路与条件跳过。没有并行、没有投票、没有加权集成。
**稳妥改写**：
> "三级检测器分级串行：确定性规则先行，规则命中高危即短路止步；仅当存在未决信号才升级到外部模型判定——协同的目标是控制升级面与调用成本，而非投票集成。"

## 🟡 轻度风险（需限定语）

### R13 展示界面截图不加"仿真"限定
**风险原因**：所有决策的 `evaluation_mode` 被硬编码为 `simulation`，服务层还会主动拒绝任何非 simulation 的决策。界面自带 `SIMULATION / 仿真` 徽标与"不可用于实际拦截"提示。裁掉这些元素构成误导。
**改写**：保留徽标，图注注明"仿真模式"。

### R14 Showcase 页截图被描述为真实运行结果
**风险原因**：该页数据是手写 fixture，含手填的 `elapsed_ms` 与 2884ms 总耗时，零 API 调用。页面自身标注"演示数据"。
**改写**：图注必须含"演示数据"或"示意"。

### R15 「全部测试通过」
**风险原因**：实测引擎侧 593 中 15 红（源于某次提交把预算放大 40–360 倍未同步测试），后端 291 中 60 红（同一条 Windows POSIX 权限门，非逻辑缺陷，但意味着 SQLite 持久层在本机未被验证）。
**改写**：不提测试总数；或诚实写"核心边界模块测试全绿（脱敏 48/48、令牌边界 56/56、判官协议 68/68、准入 71/71），另有部分测试因预算参数调整与平台权限模型待同步"。

### R16 引用 LLMmap / Pasquini 论文作为技术基础
**风险原因**：仓库内确有该 PDF，但全源码 grep `pasquini|llmmap|usenix` **零命中**。该论文属资产测绘方向的背景阅读，与沙箱引擎无实现关联。
**改写**：不引用。要引学术基础就引语料来源——AgentDojo / ToolEmu / deepset prompt-injections / OASST1，这四个是真的按 revision 与逐条哈希锁定的。

### R17 「支持 OpenAI / 多模型厂商」暗示广泛兼容
**风险原因**：协议白名单**恰好两条**（Responses API、Chat-Completions-JSON），端点强制 HTTPS + FQDN，本地模型硬绑 `qwen3:8b` 且 digest 双重校验。
**改写**：
> "外部判定模型通过显式白名单的两种协议适配接入，端点受 HTTPS 与域名策略约束；本地模型按内容摘要锁定版本，启动与每次响应各校验一次。"

### R18 「provenance / 来源溯源」暗示密码学溯源
**风险原因**：`provenance_ref` 确实全链携带并参与权威比对，但格式校验仅"非空"，无签名、无链式验证。
**改写**：说"来源声明与权威上下文逐字段比对"，不说"密码学溯源"。
