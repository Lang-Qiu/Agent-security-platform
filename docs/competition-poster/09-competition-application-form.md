## 2. 作品名称候选

**候选 1：智鉴界——智能体安全判定与审计平台**

“智”指智能体，“鉴”指检测与复核，“界”指信任边界和数据边界。名称具有项目辨识度，副标题直接说明统一判定与审计能力，适合正式竞赛申报；“判定”也不会误导为操作系统级隔离或已经生效的运行时拦截。

**候选 2：智鉴沙箱——智能体风险检测与安全决策平台**

强调风险识别与策略决策，也保留 Sandbox Engine 的项目辨识度。适合正式申报，但答辩时需要主动说明这里的“沙箱”是内容安全判定沙箱，不是 syscall 或进程隔离沙箱。

**候选 3：AgentTrust 智能体输入、输出与工具调用安全评估平台**

强调三阶段联合评估和信任边界。适合技术类竞赛，信息准确但名称较长。

**候选 4：隐界 Agent Security——隐私保护型智能体安全判定平台**

强调外部判定前的脱敏、令牌化和回泄复查，是差异化最强的命名。适合突出专项创新，但对项目的审计与平台能力覆盖较弱。

**候选 5：AgentGuard——多检测器智能体风险评估平台**

强调智能体、多检测器和风险评估，英文名称直接。适合技术类申报，但名称较通用，项目辨识度不如候选 1。

**推荐：智鉴界——智能体安全判定与审计平台**

**理由：**名称把智能体、检测复核与安全边界压缩为一个有辨识度的中文品牌，副标题准确覆盖检测、归约和审计三类已实现能力；既避免只使用内部模块名，也不暗示尚未验证的操作系统隔离、实时拦截或检测效果。

## 3. 作品创新性

### 技术版

1. **从单点内容检查扩展为智能体三阶段联合判定。** 与仅检查静态文件或单条文本的方案相比，本作品把用户输入、模型输出和工具调用请求纳入同一版本化契约，在来源类型、信任等级和执行阶段上下文中形成结构化 Finding，避免把 Agent 特有风险简化为普通关键词命中。
2. **外部模型参与判定，但不接收未经脱敏的原始内容。** 对需要升级的信号，系统先建立 `etok:` 令牌边界，再执行十类确定性脱敏，并在出口对敏感原子进行归一化、百分号解码和 Base64 解码复查；任一敏感原子重现即硬失败，且不会调用外部判定模型。其本质区别是把“尽力脱敏”改造成“带出口否证的安全边界”。
3. **不把模型输出当作安全权威。** 本地模型和外部判定模型的输出先经过闭合 Schema、解析复验和 obligation 绑定表校验；风险类别与受影响主体必须来自本地预登记关系，模型只能在受限枚举内提供结果、严重度和置信度。未知 obligation 会使整份响应作废，模型无法通过自造字段扩大判定权限。
4. **多检测器不是简单串接，而是由统一策略形成一个结论。** 确定性规则、本地模型和外部判定按固定顺序执行，高风险规则命中可短路后续槽位，未决信号才升级；所有合格 Finding、失败和超时最终进入同一策略归约器，输出 `no_detected_risk`、`risk_detected` 或 `indeterminate` 三态结论，并在返回前进行决策一致性复核。

### 易读版

1. 普通内容安全往往只看“一段话有没有风险”，本作品还看这段内容来自用户、模型还是外部记忆，以及它是否正在触发工具调用。
2. 需要外部大模型协助时，系统先脱敏和令牌化，再检查脱敏结果中是否重新出现敏感信息；检查失败就不发送。
3. 大模型的回答不能直接成为结论。它必须与系统预先登记的风险任务逐项对账，风险类型和对象仍由本地系统掌握。
4. 规则、本地模型和外部判定不是各自给分后简单投票，而是按风险逐级调用，再由统一策略给出可解释的最终决策。

### 最终推荐版

1. **从“扫描一段内容”走向“理解智能体正在做什么”。** 作品统一评估用户输入、模型输出和工具调用请求，并结合内容来源、信任等级与执行阶段生成结构化风险发现，面向提示注入、指令覆盖、工具劫持、记忆投毒等智能体特有风险进行判定。
2. **让外部模型参与判定，同时守住原始内容边界。** 待升级信号必须先经过令牌化、十类确定性脱敏和出口回泄复查；敏感原子一旦重现，流程立即失败且不调用外部模型。与直接提交原始上下文的判定方式相比，本作品把隐私保护变成可检查、可失败的工程边界。
3. **把模型当作不可信信号源，而不是安全权威。** 模型返回结果必须通过严格 Schema、解析复验和本地 obligation 对账；风险类别与受影响主体由本地绑定，模型不能编造对象或扩大权限。
4. **以统一安全决策替代检测工具拼接。** 规则、本地模型和外部判定按风险逐级协同，高风险可短路、未决信号才升级，全部 Finding、失败与超时由同一策略归约器形成三态判定，并在返回前重新推导关键链路进行一致性复核。

## 4. 技术先进性

### 技术版

1. **分层检测 Pipeline 与有界调度。** 引擎以单一 `evaluate()` 入口严格串行调度 rule、local、judge 三个槽位；每槽具有准入、租约、输出边界和运行账本，高风险命中触发短路，外部判定仅处理未决 obligation，解决异构检测器的调用顺序、失败传播和不必要升级问题。
2. **统一 Finding Schema 与策略归约器。** 检测器私有输出先被规范化为带类别、严重度、置信度、主体引用和证据引用的 Finding，再由 Policy Reducer 统一处理已接受风险、未决信号、超时和引擎故障，形成 verdict、action、risk_level 一致的版本化决策，解决多检测器结果格式不一和结论冲突问题。
3. **双向隐私边界与不可信模型输出收束。** 系统同时控制“发给模型什么”和“允许模型返回什么”：出站侧执行确定性脱敏、令牌映射和敏感原子复查；入站侧执行严格 JSON Schema、解析复验和 obligation 绑定，解决外部判定引入的数据泄露与模型越权两类新风险。
4. **权威来源与信任边界建模。** 提交内容必须与受信适配器构造的权威上下文逐字段比对，JSON 使用规范等价比较；stage、authority kind、source type 共同解析 trust class，并通过 handle、nonce 和冻结对象限制跨边界替换，解决多来源内容在 Agent 链路中被混淆或冒充的问题。
5. **确定性发布与决策一致性复核。** 系统使用规范 JSON、内容哈希 Finding ID、确定性主体令牌和稳定排序生成公开结果；决策完成后重新推导资格判定、升级状态、发布映射和策略归约并逐项比对，解决安全结论难以复核和实现状态漂移的问题。
6. **平台级安全准入与可审计调用链。** 后端依次完成限流、能力令牌鉴权、作用域校验、幂等键绑定、严格读体与 Schema 校验，再调用引擎；前端只消费版本化公开契约并展示 Decision、Finding 和 Detector Run，解决从引擎能力到可用平台之间的接口治理、重复请求和错误语义问题。

### 易读版

1. 系统先用快速规则识别明确风险，再按需调用本地模型和外部判定，明确风险可提前结束，未决风险才继续升级。
2. 不同检测器的结果先变成统一的“风险发现”，再由同一个策略模块给出允许、告警、询问或拒绝建议，避免多个工具各说各话。
3. 外发内容必须先脱敏，模型返回结果也必须经过本地约束，外部模型在输入和输出两个方向都不能越过安全边界。
4. 系统记录内容来自哪里、处于哪个阶段、可信程度如何，防止外部内容伪装成系统指令或可信上下文。
5. 每条结果都有稳定的标识、证据引用和检测器运行记录，且返回前会重新核对关键决策过程。
6. Web、API、鉴权、幂等、审计和错误处理共同组成可使用的评估链路，而不是只能单独运行的算法脚本。

### 最终推荐版

1. **分层检测与按风险升级：**规则、本地模型、外部判定三个检测槽严格串行；明确高风险可短路，只有未决信号才进入更高层判定，兼顾确定性基线、语义识别能力和外部调用边界。
2. **异构结果统一归约：**各检测器输出先规范化为统一 Finding，再由策略归约器集中处理风险、未决状态、超时和故障，形成 `no_detected_risk`、`risk_detected`、`indeterminate` 三态结论及允许、告警、询问、拒绝四类动作建议。
3. **模型输入输出双向约束：**出站侧采用令牌化、十类确定性脱敏和敏感原子回泄复查；入站侧采用严格 Schema、解析复验和本地 obligation 绑定，防止外部判定同时成为数据泄露口和新的决策越权点。
4. **来源可信性建模：**将评估阶段、权威类型和内容来源共同纳入 trust class 解析，并对提交内容与权威上下文逐字段比对，解决用户输入、检索内容、长期记忆和模型输出在智能体链路中的来源混淆问题。
5. **可复核决策生成：**通过规范序列化、内容哈希标识、确定性发布顺序和决策后语义复核，使 Finding、证据引用与最终策略结论保持一致，便于重放分析与审计。
6. **平台化安全接口：**后端实现能力令牌、作用域校验、严格 HTTP 准入、幂等与内容无关审计；前端通过统一契约呈现决策摘要、风险发现和检测器运行过程，形成从提交到复核的完整闭环。

## 5. 应用前景

### 技术版

**当前可落地场景。** 作品当前以仿真安全评估平台形态，适用于企业内部 Agent、智能体开发平台和大模型应用测试环境的上线前检查；也可用于第三方 Skill、Plugin、MCP 工具及高权限自动化流程的输入、输出和工具请求安全评估。其价值是把分散的检测结果统一为可被平台消费、人工复核和审计的安全决策。

**行业推广场景。** 对金融、医疗、政务、工业和软件研发等敏感数据或高权限操作较多的行业，可部署规则优先的离线评估模式，在受控网络内增加本地模型，并在满足数据出境策略时启用经过脱敏边界的外部判定。当前适合安全测试、接入评审和仿真验证，不将其表述为已经部署生效的生产拦截系统。

**未来新场景。** 随着 Agent 从对话走向多 Agent 协作、长期记忆、自主工具调用和跨平台任务执行，安全问题会从单轮内容合规扩展为来源可信、权限使用和行为链路风险。本作品的阶段化请求契约、Detector 接口和统一 Finding/Decision 结构，可作为第三方技能生态治理和高权限自治 Agent 安全控制的演进基础；这些属于推广方向，不作为当前已完成能力申报。

### 易读版

作品首先适合“把 Agent 上线前先测一遍”的场景：企业内部智能体、Agent 开发平台、大模型应用安全测试、第三方工具和技能接入评审。用户可以检查一段输入、一次模型输出或一项工具请求，并得到带原因和证据引用的安全结论。

在金融、医疗、政务、工业和软件研发等场景中，可根据数据敏感度选择纯规则、本地模型或经脱敏后调用外部判定的模式。未来，当 Agent 具备长期记忆、协同决策和更高工具权限时，同一套来源可信与统一决策机制可继续扩展到多 Agent 和第三方工具生态治理。

### 最终推荐版

**近期可用于智能体上线前安全评估。** 面向企业内部 Agent、智能体开发平台、大模型应用安全测试和第三方 Skill/Plugin/MCP 接入评审，对用户输入、模型输出和工具请求进行仿真检测，向开发者和安全人员提供结构化 Finding、证据引用与统一决策。

**可向敏感数据与高权限行业推广。** 金融、医疗、政务、工业和软件研发等场景可按数据边界选择纯规则离线模式、本地模型模式，或在确定性脱敏后使用外部判定，支持安全测试、接入评审和策略验证。

**可应对智能体自主性持续增强的新风险。** 面向多 Agent 协作、长期记忆、自主工具调用、跨平台 Agent 和第三方工具生态，作品可基于现有阶段契约、来源可信模型和统一 Finding/Decision 机制继续扩展。随着智能体从“生成内容”走向“执行任务”，这类运行前判定与审计能力将成为传统内容安全的重要补充。

## 6. 设计完整性

### 技术版

作品交付为可联调的软件平台，而非单一算法脚本。核心包括：Sandbox Security Engine；规则、本地 Ollama 和外部判定三种检测器装配；Node.js/TypeScript 后端；React/TypeScript 前端工作台与审计页；版本化请求、决策和 API 共享契约；SQLite 幂等、能力与审计存储；300 例可复现评测语料、自动化测试和运行配置。

用户通过 `/sandbox-security/workbench` 粘贴短期能力令牌，选择用户输入、模型输出或工具请求阶段，填写检测内容和策略档位并提交。前端调用 `POST /api/sandbox/security/evaluations`，展示 verdict、action、risk_level、Findings、主体位置引用和 detector runs；API 决策契约同时携带 evidence refs。用户再通过 `/sandbox-security/audit` 调用 `GET /api/sandbox/security/audit-events` 查看不含原始内容的分页审计事件。当前公开评估链路被强制标记为 `simulation`，用于分析和验证，不宣称实际执行拦截。

运行基线为 Node.js `>=22.19.0`、`pnpm@10.0.0`。Web 前端和引擎开发可在 Windows、Linux 或 macOS 进行；后端生产存储加固依赖 POSIX 文件权限，正式部署宜使用 Linux。`rule_only` 不需要模型或外部网络；`local` 需要本地 Ollama `qwen3:8b` 及匹配摘要；`local_and_judge` 还需要受 HTTPS/FQDN 策略约束的外部端点、协议选择和密钥。核心 Web/API 演示不要求 Docker；Linux 网络隔离重放及独立 OpenClaw 宿主打包才需要对应系统能力或容器环境。

### 易读版

作品已经形成“前端可操作、后端可调用、引擎可判定、结果可审计”的完整链路。用户在 Web 工作台输入检测内容，系统返回风险结论、动作建议、风险发现和各检测器运行状态；审计页可查看不包含原始提交内容的调用记录。系统还提供公开 API、短期能力令牌、幂等处理、配置校验、自动化测试和评测语料。

最简演示只需 Node.js、pnpm 和 `rule_only` 模式，不需要外部模型或网络。需要更深层检测时，可选本地 Ollama；只有启用外部判定时才需要网络、端点和密钥。当前工作台始终标注“仿真”，用于安全分析而非真实执行拦截。

### 最终推荐版

作品以 **Web 安全工作台 + 后端 API 服务 + Sandbox Security Engine + 共享安全契约 + 审计与测试资产** 的形态交付，已经形成完整仿真使用链路：用户粘贴短期能力令牌，选择用户输入、模型输出或工具请求，提交评估后查看三态结论、动作建议、风险等级、Finding、主体位置引用和检测器运行记录，并在审计页查看不含原始内容的分页事件；API 决策契约同时保留 evidence refs 供调用方消费。

平台提供两个公开接口：`POST /api/sandbox/security/evaluations` 用于评估，`GET /api/sandbox/security/audit-events` 用于审计查询；后端同时完成作用域鉴权、严格输入准入、幂等处理、错误语义和 SQLite 存储。前后端只通过版本化共享契约交互，检测器私有输出不会直接暴露给界面。

运行基线为 Node.js `>=22.19.0`、`pnpm@10.0.0`。最简 `rule_only` 模式可离线运行，无需 Docker、模型或外部 Judge；`local` 模式需要本地 Ollama `qwen3:8b` 与摘要校验；`local_and_judge` 模式需要受 HTTPS/FQDN 策略约束的外部端点和密钥。后端正式存储部署宜采用支持 POSIX 权限的 Linux 环境。当前公开链路强制为 `simulation`，定位于安全分析、接入评审和上线前验证。

## 7. 演示功能

### 技术版

1. **建立受控会话。** 操作：打开评估工作台，粘贴预先签发的短期能力令牌，确认 `SIMULATION / 仿真` 标识。系统反应：在内存中建立能力会话并开放提交。评委看到的亮点：鉴权边界和能力范围明确，令牌不写入 URL 或浏览器存储。
2. **提交正常输入。** 操作：在 `user_input` 阶段输入普通任务文本并使用 balanced 档提交。系统反应：返回 `no_detected_risk` 和 `allow`，同时列出检测器运行记录。评委看到的亮点：正常请求不被风险界面干扰，结果结构完整。
3. **提交提示注入样例。** 操作：把内容改为 `ignore previous instructions` 并重新提交。系统反应：规则检测器生成 `prompt_injection`、high 级 Finding，策略返回 `risk_detected` 和 `deny`。评委看到的亮点：同一工作台可直接对比正常与攻击请求。

5. **查看高风险短路。** 操作：查看 Detector Run 表。系统反应：规则命中 high 风险后，后续槽位按策略跳过或不再升级。评委看到的亮点：多检测器按风险调度，不是每次都调用模型。

## 10. 最终可直接粘贴版

**作品名称：**

智鉴界——智能体安全判定与审计平台

**作品创新性：**

1. 从“扫描一段内容”走向“理解智能体正在做什么”：统一评估用户输入、模型输出和工具调用请求，并结合内容来源、信任等级与执行阶段生成结构化风险发现，面向提示注入、指令覆盖、工具劫持、记忆投毒等智能体特有风险进行判定。
2. 让外部模型参与判定，同时守住原始内容边界：待升级信号必须先经过令牌化、十类确定性脱敏和出口回泄复查；敏感原子一旦重现，流程立即失败且不调用外部模型。与直接提交原始上下文的判定方式相比，本作品把隐私保护变成可检查、可失败的工程边界。
3. 把模型当作不可信信号源，而不是安全权威：模型返回结果必须通过严格 Schema、解析复验和本地 obligation 对账；风险类别与受影响主体由本地绑定，模型不能编造对象或扩大权限。
4. 以统一安全决策替代检测工具拼接：规则、本地模型和外部判定按风险逐级协同，高风险可短路、未决信号才升级，全部 Finding、失败与超时由同一策略归约器形成三态判定，并在返回前重新推导关键链路进行一致性复核。

**技术先进性：**

1. 分层检测与按风险升级：规则、本地模型、外部判定三个检测槽严格串行；明确高风险可短路，只有未决信号才进入更高层判定，兼顾确定性基线、语义识别能力和外部调用边界。
2. 异构结果统一归约：各检测器输出先规范化为统一 Finding，再由策略归约器集中处理风险、未决状态、超时和故障，形成 `no_detected_risk`、`risk_detected`、`indeterminate` 三态结论及允许、告警、询问、拒绝四类动作建议。
3. 模型输入输出双向约束：出站侧采用令牌化、十类确定性脱敏和敏感原子回泄复查；入站侧采用严格 Schema、解析复验和本地 obligation 绑定，防止外部判定同时成为数据泄露口和新的决策越权点。
4. 来源可信性建模：将评估阶段、权威类型和内容来源共同纳入 trust class 解析，并对提交内容与权威上下文逐字段比对，解决用户输入、检索内容、长期记忆和模型输出在智能体链路中的来源混淆问题。
5. 可复核决策生成：通过规范序列化、内容哈希标识、确定性发布顺序和决策后语义复核，使 Finding、证据引用与最终策略结论保持一致，便于重放分析与审计。
6. 平台化安全接口：后端实现能力令牌、作用域校验、严格 HTTP 准入、幂等与内容无关审计；前端通过统一契约呈现决策摘要、风险发现和检测器运行过程，形成从提交到复核的完整闭环。

**应用前景：**

近期可用于企业内部 Agent、智能体开发平台、大模型应用安全测试和第三方 Skill/Plugin/MCP 接入评审，对用户输入、模型输出和工具请求进行上线前仿真检测，向开发者和安全人员提供结构化 Finding、证据引用与统一决策。金融、医疗、政务、工业和软件研发等场景可按数据边界选择纯规则离线模式、本地模型模式，或在确定性脱敏后使用外部判定，支持安全测试、接入评审和策略验证。面向多 Agent 协作、长期记忆、自主工具调用、跨平台 Agent 和第三方工具生态，作品可基于现有阶段契约、来源可信模型和统一 Finding/Decision 机制继续扩展。随着智能体从“生成内容”走向“执行任务”，这类运行前判定与审计能力将成为传统内容安全的重要补充。

**设计完整性：**

作品以 Web 安全工作台、后端 API 服务、Sandbox Security Engine、共享安全契约、审计与测试资产的形态交付，形成完整仿真使用链路：用户粘贴短期能力令牌，选择用户输入、模型输出或工具请求，提交评估后查看三态结论、动作建议、风险等级、Finding、主体位置引用和检测器运行记录，并在审计页查看不含原始内容的分页事件；API 决策契约同时携带 evidence refs。平台提供评估与审计两个公开接口，后端实现作用域鉴权、严格输入准入、幂等处理、错误语义和 SQLite 存储，前后端通过版本化共享契约交互。运行基线为 Node.js `>=22.19.0`、`pnpm@10.0.0`；最简 `rule_only` 模式可离线运行，无需 Docker、模型或外部 Judge；`local` 模式需要本地 Ollama `qwen3:8b` 与摘要校验；`local_and_judge` 模式需要受 HTTPS/FQDN 策略约束的外部端点和密钥。后端正式存储部署宜采用支持 POSIX 权限的 Linux 环境。当前公开链路强制为 `simulation`，用于安全分析、接入评审和上线前验证。

**演示功能：**

1. 进入仿真评估工作台，粘贴预先签发的短期能力令牌，选择 `user_input` 与 balanced 策略档位。
2. 输入普通任务文本，展示系统返回 `no_detected_risk / allow` 和检测器运行记录。
3. 输入 `ignore previous instructions`，展示 `prompt_injection`、high 级 Finding 及 `risk_detected / deny` 决策。
4. 查看 subject refs 和 Detector Run，说明风险主体、发现来源及其进入最终决策的过程。
5. 展示 high 风险规则命中后的短路状态，说明后续模型仅在需要时参与。
6. 进入内容无关审计页并翻页，展示事件可追踪而原始提交内容不被再次暴露。
7. 运行脱敏器与 `etok:` 边界的定向测试，证明敏感原子重现会使流程硬失败，并保持外部判定零调用。

## 去重检查结论

- “三级检测”在创新性中强调**区别于单一检测器**，在技术先进性中强调**串行、短路和按需升级**，在设计完整性中只作为**可选部署模式**，在演示中只展示**运行记录与短路动作**。
- “Finding/Decision”在创新性中强调**不是工具拼接**，在技术先进性中强调**Schema 与归约机制**，在设计完整性中强调**前后端契约**，在演示中强调**评委可见证据**。
- “脱敏边界”在创新性中承担**差异化价值**，在技术先进性中说明**双向约束机制**，在应用前景中只说明**敏感行业的部署选择**，在演示中通过**定向测试**提供证据。
- 应用前景未重复底层实现；设计完整性未重复市场比较；演示功能全部写成现场动作，没有加入实验性 OpenClaw 生效、外部 Judge 联网、检测质量达标或 OS 级隔离等不稳定内容。
