## 图 1 — 总体架构图（需自绘）

**展示什么**：两条并行入口共用同一判定引擎的真实拓扑。

```
┌──────────────┐        ┌───────────────────────┐
│ 前端控制台    │──HTTP─▶│ 后端 (公开监听 :3000)   │
│ 评估工作台    │        │ 有序准入 → 幂等 → 并发闸 │
│ 审计视图      │◀──────│ 审计事件日志 (SQLite)   │
└──────────────┘        └───────────┬───────────┘
                                     │ 进程内调用
┌──────────────┐  进程内直接调用      ▼
│ 智能体运行时  │────────────▶┌──────────────────────┐
│ 插件 (四道    │             │  安全判定引擎         │
│ 生命周期栅栏) │──审计事件──▶│  三检测槽串行         │
└──────────────┘  (内部监听)  └──────────────────────┘
                                     │
                    ┌────────────────┼────────────────┐
                    ▼                ▼                ▼
              规则检测器        本地模型检测器    外部判定模型
              (确定性)         (digest 双校验)   (仅经脱敏边界)
```

**作用**：一图说清"引擎是共享内核，不是某个 API 的附属品"，同时暴露"外部判定模型被隔离在脱敏边界之后"这一核心设计。

**⚠️ 绘图硬约束（避免虚假连线）**：
- **不要**画「智能体插件 → 后端公开 API → 引擎」。已核实公开评估 API 全仓零调用点，插件是进程内直接调用引擎的。画错等于虚假陈述。
- 插件到后端的**唯一**连线是审计事件（内部监听），必须标注为"仅审计"。
- 智能体运行时那一块建议加浅色底或虚线框，标注"设计已实现、当前环境未启用"。

**图注建议**：
> 图 1 总体架构。判定引擎作为共享内核，同时服务于前端评估工作台与智能体运行时插件；外部判定模型被隔离在确定性脱敏边界之后。虚线框部分为已实现但当前环境未启用的运行时集成。

## 图 2 — 核心判定流程图（需自绘）

**展示什么**：单次评估的三槽串行 + 短路 + 脱敏边界 + 自校验，即"证据链是怎么长出来的"。

```
输入(三阶段之一) → 来源权威绑定 → 内容句柄化 → 策略档位

  ┌─ 规则槽 ──────── 命中高危 ──▶ 短路，跳过后续两槽
  │      │
  │      └─ 未短路
  ▼
  ├─ 本地模型槽 ──── digest 校验（启动 + 每次响应）
  │      │
  │      └─ 无未决信号 ──▶ 不调用外部判定
  ▼
  └─ 外部判定槽（仅当存在未决信号）
         │
         ├─ 令牌化 (etok:)  ← 原始句柄不出境
         ├─ 十类确定性脱敏
         ├─ 出口反向验证（多重解码复查零回泄）
         │     └─ 失败 ──▶ 判定模型零调用，路径终止
         ├─ 外部模型返回
         └─ 义务账目绑定校验 ← 未登记 id ⇒ 整份作废
                                类别/主体取自本地
  ▼
发现发布（确定性排序 + 位置级证据引用）
  ▼
策略归约（fail-closed：任一失败向更严方向抬升）
  ▼
语义自校验（重算全链比对，不一致则拒绝出具）
  ▼
决策：允许 / 告警 / 询问 / 拒绝
```

**作用**：这是**最能得分的一张图**。三个创新点（内容不出境、模型输出不被信任、决策自我否证）在一张图里同时可见，且每个环节都对应真实代码。

**图注建议**：
> 图 2 核心判定流程。三级检测器串行协同，外部判定模型仅在存在未决信号时被调用，且必须穿过确定性脱敏与令牌化边界；模型返回结论须命中本地预登记的义务账目方被采纳。引擎在出具决策前重算全链自我核验。

## 图 3 — 平台实际运行界面

**取图位置**：`.runtime/landing-audit/workbench.png`（已存在），或重拍：
```
npm run dev --prefix frontend      # 默认 5173 端口
# 路由 /sandbox-security/workbench
```

**展示什么**：左右双栏工作台。左栏能力令牌面板 + 评估请求表单（三阶段单选、双策略档位、多来源内容项、实时字节计量条）；右栏决策摘要（判定/动作/风险等级三标签 + `SIMULATION 仿真` 徽标）、风险发现表、检测器执行表。

**两种可选状态**：
- **完整状态**（需后端 + 真实能力令牌）：证明真实往返。可信度最高，配置成本也最高（需 WSL 内 Ollama + `mint-capability.sh`）。
- **预检状态**（无需后端）：令牌为空时枚举违规原因、提交按钮禁用、字节计量条实时。能体现 fail-closed，视觉较朴素。

**⚠️ 硬约束**：
- 界面上的 `SIMULATION / 仿真` 徽标与"不可用于实际拦截"提示**不要裁掉**。这是诚实性的可视证明，评委看到反而加分；裁掉则构成误导。
- 若截图时后端不可用，**不要**改用 `/results/sandbox` 页面充数——该页默认走 mock 数据，且属于另一个 feature。

**图注建议**：
> 图 3 评估工作台实际运行界面。左侧提交评估请求，右侧呈现决策摘要、风险发现与逐检测器执行记录（含状态与耗时）。界面显式标注"仿真"模式，决策不用于真实拦截。

## 图 4 — 证据链细节（推荐）或语料构成（备选）

### 4-A 证据链细节（推荐）

**取图位置**：`.runtime/landing-audit/showcase.png`，或重拍 `/sandbox-security-showcase` 页——点击"开始演示"后进入第三幕，展开任一发现卡片。

**展示什么**：单条发现的完整证据结构——风险类别、严重级、置信度、`reason_code`、检测器标识与版本、**位置级引用（仅位置，不含内容）**。

**为什么选这张**：它是"可审计"与"隐私保护"两个卖点的具象化。发现只指向"第几个来源的第几字节区间"，不回显原文——这正是脱敏设计在 UI 层的延续。

**⚠️ 硬约束（重要）**：
- 该页数据是**手写 fixture**（含 `elapsed_ms` 与总耗时 2884ms），页面自身标注了"演示数据"。
- 图注**必须**含"演示数据"或"示意"字样，**不得**写"某次真实运行结果"。
- 页面上的"本页决策为预置演示数据"提示条不要裁掉。
- 该页样式与组件目前处于未提交状态，需在当前工作树截图。

**图注建议**：
> 图 4 单条风险发现的证据结构（演示数据）。每条发现携带类别、严重级、置信度、原因码、检测器标识与位置级引用；引用仅指向内容位置，不回显原文，与脱敏边界的设计一致。
